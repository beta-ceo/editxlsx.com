Both products edit spreadsheets in the browser. They optimize for different constraints.

## Quick comparison

| | EditXLSX (local) | Excel for the web |
| --- | --- | --- |
| Cost to open a file | Free | Free with Microsoft account |
| Account required | No (local path) | Yes |
| Where the file lives while editing | Your browser tab | Microsoft cloud (OneDrive) |
| Desktop install | Not needed | Not needed |
| VBA / Power Query depth | Not the goal | Stronger Microsoft ecosystem |
| Live Microsoft co-authoring | No | Yes (Microsoft stack) |
| Optional personal cloud here | $5/year on this site | OneDrive / 365 |

## When to use this editor

- You refuse (or cannot create) a Microsoft account on this machine
- You want a quick open–edit–download without OneDrive
- You want a **cheap** personal sync ($5/year) instead of a full 365 seat
- You are on Chromebook / Linux and only need everyday `.xlsx` fidelity

## When to use Excel for the web

- Your team already lives in Microsoft 365
- You need Microsoft co-authoring, comments, and sharing links
- You rely on Excel features that only the Microsoft stack provides

## Honest limits

Neither this page nor Excel for the web replaces every desktop Excel workflow. For VBA and heavy models, use desktop Excel.

## How to try the local path

1. Open the editor — no Microsoft sign-in.
2. Pick an `.xlsx` from your device.
3. Edit and download.
4. Optionally [sign in](/login) later for $5/year cloud workbooks on this site.
